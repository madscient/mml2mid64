# 09. SMF 出力

> 完成度: 構造・順序・ランニングステータス・重複除去を実測で確定。`[?]` が 3 件。
>
> **バイト一致を目指すなら、この章が最も重要です。**

## 9.1 ヘッダ

```
4D 54 68 64  00 00 00 06  ffff  nnnn  dddd
MThd         長さ 6        形式   本数  分解能
```

| 項目 | 値 | 出典 |
| --- | --- | --- |
| 形式 | `0001`（既定）／ `0000`（`-f` 指定時） | `[obs]` |
| トラック本数 | FORMAT 1: テンポマップ 1 本 + MML のトラック数<br>FORMAT 0: 常に 1 | `[obs]` |
| 分解能 | `#timebase` の値をそのまま 16 ビットで書く | `[obs]` |

トラック本数は **16 ビットで書かれます**。`[fork]`
（オリジナル版は 1 バイトでしか書いておらず、64 本を超えると壊れました）

## 9.2 FORMAT 1 の構造

```
MThd
MTrk  ← 第 1 トラック（テンポマップ）
MTrk  ← MML のトラック（出力順序は 04-tracks.md 4.6）
MTrk
…
```

### 第 1 トラック（テンポマップ）の内容

**必ず次の 2 つで始まります。指定が無くても長さ 0 で出力されます。** `[obs]`

```
00 FF 03 ll …    #title の内容（Sequence/Track Name）
00 FF 02 ll …    #copyright の内容（Copyright Notice）
```

続いて、全トラックから集められた次のイベントがステップタイム順に並びます。

- テンポ（`t`, `t(`, `t)`, `FT`, `UT`, `IT`）→ `FF 51 03 tttttt`
- 拍子（`BT`）→ `FF 58 04 nn dd cc bb`

最後に `00 FF 2F 00`（End of Track）。

### MML のトラック

トラック名（`Cn"…"`）が指定されていれば、先頭に `00 FF 03 ll …` が入ります。`[obs]`

その後、そのトラックのイベントがステップタイム順に並び、最後に `00 FF 2F 00`。

## 9.3 FORMAT 0 の構造（`-f`）

すべてのトラックが 1 本の MTrk にマージされます。`[obs]`

```
00 FF 03 ll …    #title
00 FF 02 ll …    #copyright
（全トラックのイベントを絶対 tick 順にマージ）
00 FF 2F 00
```

**同じ tick に複数トラックのイベントがある場合、トラックの出力順序
（[04-tracks.md](04-tracks.md) 4.6）で並びます。** `[obs]`

実測（`A C1 v10 c` / `B C2 v20 d`）:

```
00 FF 03 00  00 FF 02 00
00 B0 07 0A  00 90 3C 64  00 B1 07 14  00 91 3E 64
2F 90 3C 00  00 91 3E 00
00 FF 2F 00
```

tick 0 に A のボリューム→ノートオン、続いて B のボリューム→ノートオン。
tick 47 に A のノートオフ、B のノートオフ。`[obs]`

## 9.4 デルタタイム

標準の可変長数値です。`[obs]`

```
576 ステップ  →  84 40
```

## 9.5 ランニングステータス

**同じステータスバイトが続く場合は省略されます。** `[obs]`

```
A C1 c d
→ 90 3C 64  2F 3C 00  01 3E 64  2F 3E 00
     ↑ 以降 90 は省略される
```

### ⚠ メタイベントと SysEx はランニングステータスを打ち切りません

これは一般的な SMF の慣行と異なりますが、**実装はこうなっています。**
再実装で「打ち切る」と書くとバイト列が一致しません。`[obs]`

```
A C1 v10 v20 EXx41,xf7 v30 v40
→ 00 B0 07 0A  00 07 14  00 F0 02 41 F7  00 07 1E  00 07 28
                  ↑省略                     ↑ F0 の後も省略が続く

A C1 v10 v20 WT"x" v30 v40
→ 00 B0 07 0A  00 07 14  00 FF 01 01 78  00 07 1E  00 07 28
                                            ↑ FF の後も省略が続く
```

`=0` の状態書き戻しの経路だけは、エクスクルーシブの後にランニングステータスを
打ち切ります（バイト数の見積もりと一致させるため）。`[fork]` `[?]`

## 9.6 ノートオフの表現

キーオフベロシティが 0 なら「ノートオン、ベロシティ 0」、0 以外なら
`0x8n`（Note Off）です。詳細は [05-time.md](05-time.md) 5.5。`[obs]`

前者はランニングステータスの対象になりますが、後者はステータスバイトが変わるため
ならないことに注意してください。

## 9.7 重複除去

コントロールチェンジとピッチベンドは、**現在値と同じ値なら出力されません。**
[07-commands.md](07-commands.md) 7.2 を参照。`[doc]` `[obs]`

> **重複除去されるのは「処理系が現在値を追跡している 5 つの状態」だけです。** `[obs]`

| 対象 | 重複除去 |
| --- | --- |
| ボリューム（CC#7） | **する** |
| エクスプレッション（CC#11） | **する** |
| パンポット（CC#10） | **する** |
| モジュレーション（CC#1） | **する** |
| ピッチベンド | **する** |
| 上記 5 つへのエンベロープ／LFO の書き込み | **する** |
| `y` で上記 5 つの CC 番号へ書いた場合 | **する**（対応するコマンドと同じ状態を共有） |
| チャンネルプレッシャー（`G`、`Dn`） | しない |
| バンクセレクト（`H`、CC#0/32） | しない |
| プログラムチェンジ（`@`、`Cn`） | しない |
| RPN / NRPN のデータ（CC#6） | しない（アドレスの CC#101/100/99/98 はする） |
| ペダル系（`P` / `X`、CC#64〜68） | しない `[fork]` |
| その他の CC（`y91` など） | しない |
| テンポ（`FF 51`） | しない |
| メタイベント・SysEx | しない |

`s` コマンドと `Cn` によるチャンネル変更は、次の 1 回だけ解除します。

詳細と実測例は [07-commands.md](07-commands.md) 7.2。

## 9.8 イベントの順序（同一 tick 内）

1 つのトラックの中で同じ tick に複数のイベントが発生する場合の順序です。

| 状況 | 順序 | 出典 |
| --- | --- | --- |
| コマンドで書いたイベント同士 | MML に書いた順 | `[obs]` |
| ノートオフとノートオン | [05-time.md](05-time.md) 5.6 参照 | `[obs]` |
| 音長 0 の和音 | 書いた順にノートオン | `[obs]` |
| エンベロープの書き込みとノートオフ | **エンベロープが先** | `[obs]` |
| ノートオフと次のノートの基準値書き戻し・ノートオン | ノートオフ → 基準値書き戻し → ノートオン | `[obs]` |
| `F*` と `I*` が同じ tick に書く場合 | 2 イベントが並ぶ。前後関係は `[?]` | `[obs]` |
