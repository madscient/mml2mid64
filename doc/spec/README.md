# mml2mid64 言語仕様書

このディレクトリは、mml2mid64 が受理する MML 言語と、それが生成する標準MIDIファイル
（SMF）を、**外部から観測できる挙動だけで**記述したものです。

## この文書の目的

1. **再実装のための正本。** この文書だけを読んで、既存の実装を一切参照せずに、
   同じ MML を同じ SMF にコンパイルする処理系を書けること。
2. **現行実装の挙動の記録。** 文書化されていなかった既定値・出力順序・端数処理を
   明文化し、回帰テストの根拠にすること。

## 記述の方針（重要）

この文書には、**外部から観測できる挙動だけ**を書きます。具体的には:

| 書くもの | 書かないもの |
| --- | --- |
| 入力 MML と出力バイト列の対応 | ソースの関数名・変数名・ファイル構成 |
| 状態の初期値と遷移規則 | データ構造の形（配列・構造体・テーブル） |
| エラーになる条件とメッセージ | 処理の順序や分岐の組み方、アルゴリズムの書き方 |
| 端数処理・上限・優先順位 | 最適化の手口 |

これは著作権上の理由によります。C 実装の表現（コードの書き方）は原著者の著作物です。
**この文書を経由して実装の表現が新実装へ流れてはなりません。** 事実（何が起きるか）は
著作権の対象ではないので自由に記述できますが、それをどう実現しているかは書きません。

同じ理由で、`org-doc/` の文面は引き写しません。事実の抽出元としてのみ使います。

## 出典タグ

各記述には出典を示すタグを付けます。信頼度がタグごとに違うため、実装時の扱いも変わります。

| タグ | 意味 | 実装時の扱い |
| --- | --- | --- |
| `[doc]` | オリジナル配布物の説明書に記載がある | 信頼してよい。ただし説明書と実装が食い違う例が既知（後述）なので、重要な箇所は `[obs]` で裏を取る |
| `[obs]` | 現行実装の出力バイト列を実測して確認した | **最も強い**。バイト一致を目指すならこれに従う |
| `[fork]` | 本フォークが追加・変更した仕様（`doc/CHANGES.md` が正本） | オリジナルには無い。移植先に入れるかは選択できる |
| `[?]` | 未確定。要検証 | 実装前に必ずプローブで潰すこと。[99-open.md](99-open.md) に一覧 |

`[doc]` と `[obs]` が食い違う場合は `[obs]` が正です。両者の既知の食い違いは
[11-quirks.md](11-quirks.md) に記録します。

## 適合性の定義

再実装がこの仕様に適合しているとは、次を満たすことを言います。

1. **バイト一致。** 同じ入力 MML・同じオプションに対し、生成される SMF が現行実装の
   出力とバイト単位で一致する。これが最終的な判定基準です。
2. **診断の一致。** エラーになる入力ではエラーになり、正常終了する入力では正常終了する
   （メッセージの文面までの一致は求めない）。
3. **進捗表示の一致は求めない。** `S` コマンドやトラック集計の表示形式は仕様外とします。

適合性の検証は黒箱で行います。手順は [12-conformance.md](12-conformance.md) を参照。

## 用語

| 用語 | 意味 |
| --- | --- |
| **ステップ** | タイムベースを分解能とする時間の単位。SMF の tick と 1:1 で対応する |
| **タイムベース** | 4分音符あたりのステップ数。SMF ヘッダの division に等しい |
| **ステップタイム** | トラック先頭からの累積ステップ数。SMF の絶対 tick に等しい |
| **主トラック** | `A` のように英大文字で始まり、従属番号を持たないトラック |
| **従属トラック** | `1A` のように先頭に数字を持つトラック |
| **トラック状態** | オクターブ・ベロシティ・音長などの、トラックごとに独立して持つ値 |
| **チャンネル状態** | ボリューム・ベンドなど、MIDI チャンネルごとに1つしか持てない値 |
| **重複除去** | 直前に送った値と同じ値のコントロールチェンジ等を出力しない最適化 |
