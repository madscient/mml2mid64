# 08. エンベロープと LFO

> 完成度: 補間・端数処理・位相・出力形式を実測で確定。立ち上がりの量子化と
> `F*`＋`I*` の合成が未解決。`[?]` が 4 件。

3 系統あります。**対象を表す 2 文字目は 3 系統で共通です。**

| 先頭 | 系統 | 起動 |
| --- | --- | --- |
| `F` | エンベロープ | **ノートオンのたびに毎回**開始 |
| `U` | 第 2 エンベロープ | **コマンドが書かれた時点**で開始。音符・休符と無関係 |
| `I` | LFO（振幅変調） | **ノートオンのたびに毎回**開始 |

| 2 文字目 | 対象 | 出力 |
| --- | --- | --- |
| `E` | エクスプレッション | CC#11 |
| `B` | ベンド | ピッチベンド（MSB のみ） |
| `W` | 2 バイトのベンド | ピッチベンド（14 ビット） |
| `V` | ボリューム | CC#7 |
| `P` | パンポット | CC#10 |
| `C` | カットオフ周波数 | NRPN 1,0x20 |
| `R` | レゾナンス | NRPN 1,0x21 |
| `M` | モジュレーション | CC#1 |
| `A` | アフタータッチ（チャンネルプレッシャー） | `Dn` |
| `T` | テンポ | `FF 51`（FORMAT 1 では第 1 トラック） |

`[doc]` `[obs]`

## 8.1 エンベロープ `F*` / `U*`

```
FEn1,n2,n3,n4(,n5,n6)(,n7,n8)…
```

| 引数 | 意味 | 単位 |
| --- | --- | --- |
| n1 | **値を書き込む頻度** | ステップ数 |
| n2 | **初期変位** | 値 |
| n3 | 1 回目の変位時間 | **n 分音符指定** |
| n4 | 1 回目の変位（到達値） | 値 |
| n5, n6 | 2 回目の変位時間と変位 | |
| n7, n8 … | 以下同様 | |

- 変位の範囲は `FW` に対して −16383〜16383、`FT` を除くそれ以外は −127〜127。`[doc]`
- **`F*` は第 1 パラメータに 0 を指定すると解除**されます（`FE0` / `FB0`）。`[doc]`
- **`U*` は第 1 パラメータに 0 を指定できません。** エンベロープが終了した時点で
  自動的に解除されます。`[doc]`
- 解除の場合を除き、パラメータは **4 個以上の偶数個**でなければなりません。`[doc]`

**変位は現在値からの相対値です。** 区間内は線形補間され、n1 ステップごとに
書き込まれます。`[obs]`

### 補間と端数処理

> **書き込む値 = floor(基準値 + 変位 × t / 区間長)**
>
> **切り捨て（floor）です。** 正負どちらの変位でも、最終的な値に対して floor を
> 適用します。四捨五入でも、変位だけを 0 方向へ切り捨てるのでもありません。`[obs]`

実測 `q0 E64 FE10,0,4,±7 c4`（区間長 48、10 ステップごと）:

| t | +7 の計算値 | 出力 | −7 の計算値 | 出力 |
| --- | --- | --- | --- | --- |
| 10 | 65.458 | **65** | 62.542 | **62** |
| 20 | 66.917 | **66** | 61.083 | **61** |
| 30 | 68.375 | **68** | 59.625 | **59** |
| 40 | 69.833 | **69** | 58.167 | **58** |

四捨五入なら `+7` 側は 65, 67, 68, 70 になり、実測と合いません。`[obs]`

### 最後の点

**ゲートタイムの範囲に入っていれば、区間の終端の点も書き込まれます。** `[obs]`

```
q0 E64 FE12,0,4,12 c4    ; ゲート 48。t = 12, 24, 36, 48 の 4 点を書く
   E64 FE12,0,4,12 c4    ; ゲート 47。t = 48 は範囲外なので 3 点で終わる
```

同じ tick にノートオフがある場合、**エンベロープの書き込みが先**に出ます
（[09-output.md](09-output.md) 9.8）。`[obs]`

### 音符ごとの再スタート

> **`F*` は各ノートオンの直前に基準値へ書き戻し、そこから再スタートします。** `[obs]`

実測 `q0 E100 FE12,0,4,-48 c4 c4`:

```
tick  0 : CC11 = 100        （E100）
tick  0 : ノートオン
… 12, 24, 36, 48 で 88, 76, 64, 52
tick 48 : ノートオフ
tick 48 : CC11 = 100        ← 基準値へ書き戻し（ノートオンより先）
tick 48 : ノートオン
… 同じ列を繰り返す
```

基準値はエンベロープ開始前の値（この例では `E100` の 100）です。`[obs]`

実測 `E100 FE12,0,4,-40 c4`（timebase 48、4 分音符 = 48 ステップ）:

```
tick  0 : CC11 = 100   （E100 そのもの。エンベロープの初期値 100+0 は重複除去される）
tick 12 : CC11 = 90
tick 24 : CC11 = 80
tick 36 : CC11 = 70
```

つまり 48 ステップかけて −40 変位し、12 ステップごとに `100 − 40×t/48` を
書いています。`[obs]`

実測 `E100 UE12,0,4,-40 r4`: 音符と無関係に 0, 12, 24, 36, 48 の 5 点で
100, 90, 80, 70, 60 を書き、末尾（変位完了）まで到達します。`[obs]`

`F*` は音符のゲートタイムで打ち切られるため、最後の点まで到達しないことが
あります。`[obs]`

### 注意

n1 を小さくすると精度は上がりますが、音源への負荷が大きくなります。timebase が
大きい場合は注意してください。`[doc]`

`FB` はポルタメントの代用に使えます。`[doc]`

```
BS64 BR24 c4& FB2,0,4,32 r2
```

## 8.2 LFO `I*`

```
IEn1,n2,n3,n4(,n5)
```

| 引数 | 意味 | 単位 |
| --- | --- | --- |
| n1 | **振幅**（1〜63） | 値 |
| n2 | **値を書き込む頻度** | ステップ数 |
| n3 | **ディレイ長** | ステップ数 |
| n4 | **波長** | ステップ数 |
| n5 | **最大振幅になるまでの長さ**（省略時 0） | ステップ数 |

- 第 1 パラメータに 0 を指定すると解除されます。`[doc]`
- それ以外の場合、パラメータは **4 個か 5 個**でなければなりません。
  4 個の場合は第 5 引数を 0 とみなします。`[doc]`

### 波形は三角波です

実測 `E100 IE20,2,0,24`（振幅 20、書き込み 2 ステップごと、波長 24）:

```
100 → 106 → 113 → 120 → 113 → 106 → 100 → 93 → 86 → 80 → 86 → 93 → 100 → …
```

波長 24・書き込み間隔 2 なので 1 周期が 12 サンプル。中心値から振幅 20 まで
3 サンプルで直線的に上がり、直線的に戻ります。**三角波**です。`[obs]`

`org-doc/mml2mid.txt` の図は正弦波のように描かれていますが、実測は三角波です。
[11-quirks.md](11-quirks.md) 参照。

### 位相の起点と書き込み位置

> **位相の起点はディレイの終了時（ノートオンから n3 ステップ後）です。**
> 書き込みは `t = n3 + k × n2`（k = 0, 1, 2, …）で行われます。`[obs]`

k = 0 の点は必ず中心値なので、**重複除去によって消える**のが普通です。

実測 `q0 BS64 IB10,4,16,16 c2`（ディレイ 16、間隔 4、波長 16、振幅 10）:

```
tick 16 : 中心値 64 → 重複除去で消える
tick 20 : 74   （四分位＝ピーク）
tick 24 : 64
tick 28 : 54   （谷）
tick 32 : 64
…
```

最初に現れるイベントが tick 20 になります。`[obs]`

### 立ち上がり（第 5 引数）

n5 を指定すると、振幅が 0 から n1 まで n5 ステップかけて増えます。`[doc]` `[obs]`

**おおむね `振幅(t) = n1 × t / n5`（t ≥ n5 で n1 に固定）ですが、
量子化の規則が確定していません。** 実測値が単純な floor / round のどちらとも
±1 の範囲で食い違います。`[?]`

実測 `q0 E64 IE60,1,0,8,64 c2`（振幅 60、間隔 1、波長 8、立ち上がり 64）の
ピーク・谷での中心値からの偏差:

| t | 位相 | 実測偏差 | `60t/64` | t | 位相 | 実測偏差 | `60t/64` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2 | ピーク | +1 | 1.875 | 34 | ピーク | +31 | 31.875 |
| 6 | 谷 | −6 | 5.625 | 38 | 谷 | −36 | 35.625 |
| 10 | ピーク | +9 | 9.375 | 42 | ピーク | +38 | 39.375 |
| 14 | 谷 | −13 | 13.125 | 46 | 谷 | −43 | 43.125 |
| 18 | ピーク | +16 | 16.875 | 50 | ピーク | +46 | 46.875 |
| 22 | 谷 | −21 | 20.625 | 54 | 谷 | −50 | 50.625 |
| 26 | ピーク | +24 | 24.375 | 58 | ピーク | +53 | 54.375 |
| 30 | 谷 | −28 | 28.125 | 62 | 谷 | −58 | 58.125 |
| | | | | 66 | ピーク | +60 | 固定値 60 |

floor だと t=6（5 になるはず）、t=22（20）、t=38（35）が合わず、
逆に t=42（39）、t=58（54）は実測の方が 1 小さくなります。
**立ち上がり区間を使う MML はバイト一致しない可能性があります。**

n5 を指定しない（または 0 の）場合は、この問題は起きません。`[obs]`

実測 `q0 BS64 IB10,2,32,12,24 c2`: ノートオンから 32 ステップは何も書かず、
その後 24 ステップかけて振幅が 0 から 10 まで増えます。`[obs]`

### 重複除去との相互作用

**LFO の書き込みも重複除去の対象です。** 書き込み間隔が波長の約数で、
サンプル点がすべて同じ値になる場合、イベントが 1 つも出力されません。`[obs]`

```
BS64 IB20,12,0,24,0 c4      ; 書き込み間隔 12・波長 24 → 全サンプルが中心値
                            ; → ピッチベンドが 1 つも出力されない
```

再実装では**重複除去を LFO の書き込みにも適用してください。** これを忘れると
バイト列が一致しません。

### 値の範囲

中心値からの変位が対象の範囲（CC なら 0〜127）を越える場合はクランプされます。
実測 `IM20,2,0,24`（モジュレーション初期値 0）では、負側が 0 に張り付き、
その間の書き込みが重複除去されてデルタタイムがまとまります。`[obs]`

## 8.2.1 対象ごとの出力形式

実測で確認したもの。`[obs]`

### `FW` / `UW` / `IW` — 2 バイトのベンド

**14 ビットのピッチベンドを完全な形で書きます。**

実測 `q0 BW8192 FW12,0,4,-4000 c4`:

```
tick  0 : E0 00 40   （8192）
tick 12 : E0 18 38   （7192 = 8192 − 1000）
tick 24 : E0 30 30   （6192）
tick 36 : E0 48 28   （5192）
tick 48 : E0 60 20   （4192）
```

`FB` / `IB`（1 バイトのベンド）は LSB を常に 0 にします。

### `FA` / `UA` / `IA` — アフタータッチ

**チャンネルプレッシャー（`Dn`）を書きます。** 基準値 0 から始まります。

実測 `q0 FA12,0,4,40 c4`:

```
tick  0 : D0 00
tick 12 : D0 0A   （10）
tick 24 : D0 14   （20）… 以降ランニングステータス
tick 36 : D0 1E   （30）
tick 48 : D0 28   （40）
```

## 8.2.2 `F*` と `I*` の同時指定

**同じ対象に両方を指定すると、それぞれが独立に書き込みます。** 同じ tick に
両方の書き込みが重なる場合、**デルタタイム 0 で 2 つのイベントが並びます**
（片方が他方を上書きするのではありません）。`[obs]`

実測 `q0 E64 FE12,0,4,-24 IE8,6,0,24 c2` の先頭:

```
tick  6 : CC11 = 72
tick 12 : CC11 = 66
tick 12 : CC11 = 58     ← 同じ tick に 2 イベント
tick 18 : CC11 = 50
tick 24 : CC11 = 44
tick 24 : CC11 = 52     ← 同上
```

**2 つの値の合成規則（どちらの基準値を使い、どちらが先に出るか）は
確定していません。** `[?]` 同時指定を使う MML はバイト一致しない可能性があります。

## 8.3 テンポへの適用 `FT` / `UT` / `IT`

出力先は FORMAT 1 では第 1 トラック（テンポマップ）です。`[obs]`

実測 `t120 FT12,0,4,40 c4`:

```
tick  0 : FF 51 03 07 A1 20   （t120）
tick  0 : FF 51 03 07 A1 20   （エンベロープ開始。同じ値でも出力される）
tick 12 : FF 51 03 07 0A E2
tick 24 : FF 51 03 06 8A 1B
tick 36 : FF 51 03 06 1A 80
```

**テンポは重複除去されません。** 同じ値が連続して出力されます。`[obs]`
