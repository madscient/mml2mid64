# 10. コマンドライン・診断・デバッグマップ

> 完成度: 実測で確定。`[?]` が 3 件。

## 10.1 起動方法

```
mml2mid [オプション] MMLファイル名 [MIDファイル名]
```

| 規則 | 内容 | 出典 |
| --- | --- | --- |
| 入力の拡張子 | `.mml` は省略できる。ただし拡張子なしの同名ファイルがあればそちらが優先される | `[doc]` |
| 出力の省略 | 入力の拡張子を `.mid` に変えた名前 | `[doc]` |
| 入力が `-` | 標準入力から読む | `[doc]` `[obs]` |
| 出力が `-` | 標準出力へ書く | `[doc]` `[obs]` |

進捗表示（タイトル、各トラックの総ステップ数など）は、UNIX 版では標準エラー出力、
Windows 版では標準出力に出ます。`[doc]`

## 10.2 オプション

| オプション | 意味 | 出典 |
| --- | --- | --- |
| `-f` | FORMAT 0 で出力する（既定は FORMAT 1） | `[doc]` |
| `-tn` | 全体を n 半音移調する。`RT` のトラックは移調しない | `[doc]` |
| `-x` | `>` と `<` の効果を逆にする（`#swap<>` と同じ） | `[doc]` |
| `-v` | `)` と `(` の効果を逆にする（`#swap()` と同じ） | `[doc]` |
| `-m` | 文字列がシフトJISかどうかの仮定を反転する | `[doc]` |
| `-w` | 理解できない文字をエラーにせず警告して無視し、続行する | `[doc]` |
| `-c` | 旧版の未文書の挙動を模倣する | `[doc]` |
| `-g` | デバッグマップ（`.mmlmap.json`）を出力する | `[fork]` |
| `-g2` | 同上（イベント単位の表を含む） | `[fork]` |
| `--diag=json` | エラー・警告を 1 行 1 JSON として標準エラーにも出す | `[fork]` |

- **`-t` 以外はトグルです。** 偶数回指定すると元に戻ります。`[doc]`
- まとめ書きできます（`-fxt5` = `-f -x -t5`）。`[doc]`
- 環境変数 **`MML2MID_OPTIONS`** にオプションを書いておけます。`[doc]`

### `-c` が模倣する挙動

1. **行頭が空白の行を注釈行と見なす**（継続行を除く）。`[doc]` `[obs]`
2. **`/* */` が閉じていなくてもエラーにしない。** `[doc]` `[obs]`

## 10.3 終了コードと診断

| 状況 | 終了コード | 出典 |
| --- | --- | --- |
| 正常終了 | 0 | `[obs]` |
| エラー | 1。**出力ファイルを残さない** | `[obs]` |

**エラーは最初の 1 件で打ち切ります。複数エラーの同時報告はできません**
（警告は複数出ます）。`[fork]`

### 人間向けのメッセージ

```
ERROR!  command 'Z{....}' is wrong in line 1.
```

`#include` した先で起きた場合はファイル名も付きます。
`# 行番号 "ファイル名"` マーカがある場合はそれに従って復元されます。`[doc]`

### `--diag=json` `[fork]`

同じ内容を、標準エラーへ **1 行 1 オブジェクトの JSON** としても出します。
人間向けのメッセージは変わりません。

```json
{"severity": "error", "code": 50, "file": "…/d.mml", "line": 1, "message": "command 'Z{....}' is wrong"}
```

| フィールド | 内容 |
| --- | --- |
| `severity` | `"error"` / `"warning"` |
| `code` | エラー番号 |
| `line` | 行番号（`#include` 展開後の復元済み） |
| `file` | ファイル名（同上） |
| `message` | 人間向けメッセージから末尾の `in line N.` を除いたもの |

## 10.4 デバッグマップ `-g` / `-g2` `[fork]`

MIDI tick と MML ソース行の対応表を、出力 MIDI の隣に `.mmlmap.json` として
書きます。統合環境が「再生位置に合わせてソース行をハイライトする」
「カーソル行から再生する」ために使います。

**形式の正本は [doc/DEBUGMAP.md](../DEBUGMAP.md) です。** ここでは要点だけ記します。

```json
{
  "version": 1,
  "generator": "mml2mid 5.30b (mml2mid64 fork)",
  "level": 1,
  "timebase": 48,
  "format": 1,
  "files": ["…/g.mml"],
  "tracks": [
    {"index": 0, "kind": "tempo", "name": "", "channel": -1},
    {"index": 1, "kind": "mml",   "name": "", "channel": 0, "trackid": "0A"}
  ],
  "tempo": [],
  "lines": [ [1, 0, 0, 1] ]
}
```

再実装で満たすべき性質:

- **`-g` を付けても SMF は 1 バイトも変わりません。** `[fork]`
- 行番号は、**コマンドを取り出した時点**のものを使います。音長の先読みが行末を
  越えると `cur_line` 相当の値は次の行へ進んでしまうため、行の最後の音符が次の行の
  ものとして記録されてしまいます。`[fork]`
- `#include` の行・ファイル復元は、エラー報告と同じ規則で行います。`[fork]`
- **既知の限界:** マクロ本体の中身は、呼び出し行に潰れて記録されます。`[fork]`

## 10.5 WebAssembly ビルド `[fork]`

Emscripten でビルドできます。**生成される SMF もデバッグマップもネイティブ版と
バイト単位で一致します。** `[fork]`

ファイル入出力は全て RAM 上で扱われるため、ソースの変更なしにビルドできます。
Node の `NODEFS` で実ワークスペースをマウントすれば `#include` も解決できます。
