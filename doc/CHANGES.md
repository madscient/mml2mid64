# オリジナル版との差分

本リポジトリは **mml2mid Version 5.30b**（門田暁人・藤井秀樹（MKR）・黒田久泰・
新出尚之 の各氏による作品）のフォークです。ここでは、**オリジナル版を使っていた方
から見て何が変わったか**をまとめます。

開発側の視点での時系列の変更履歴は [STATUS.md](STATUS.md) を参照してください。
オリジナル配布物のドキュメント一式は [`org-doc/`](../org-doc/) にそのまま残して
あります。

- [エラーメッセージの追加](#エラーメッセージの追加)

## いちばん大事なこと

**既存のMMLは、書き直さずにそのまま使えます。**
MMLの拡張（`Y` コマンドの追加、`@` の括弧付き引数、`P` / `X` の引数、トラック名の
2文字目、`` ` `` によるノートオフとポルタメントソースノート指定、`#ampasandtie`
による `&` のタイ/スラー化、`~` によるノート連結と自動ポルタメント、`${名前}` に
よる長い名前の／引数つきマクロ、`i`/`j` によるピッチベンド値の算出）は
いずれも**書き足せるように
なっただけ**で、従来どおりの書き方をしている限り解釈は変わりません。挙動が
オリジナル版と同一だったモダナイズ時点で、同梱サンプル32曲のうち28曲が、オリジナル版が
生成した `.mid` とバイト単位で完全一致することを確認しています（残り4曲の理由は
[test/README.md](../test/README.md) に記載。いずれも本フォークでの退行ではありません）。
現在は、下記の**意図した**挙動変更を踏んでいる4曲を除いた25曲が一致します。

ただし、**生成されるMIDIが変わりうる変更**があります。まず次の2件で、1件目は
不具合修正、2件目は仕様の意図的な変更です。

- 同じ行で主トラックの指定より後ろに従属トラックを並べて書いた場合（`A1A` など）、
  オリジナル版はその従属トラックを黙って捨てていました。本フォークでは正しく
  出力します。詳しくは
  「[不具合修正によって変わる挙動](#不具合修正によって変わる挙動)」を参照して
  ください。
- `r0`（音長0の休符）は、オリジナル版では常に無視されていましたが、本フォークでは
  「発音中の和音（`c0e0...` のように音長0で繋いだ音）が1つ以上あれば、それらを
  まとめてノートオフする」という意味になりました。発音中の和音が無い場合は
  従来どおり無視されるので、影響があるのは `r0` を和音の直後に書いていた場合
  だけです（通常はそのような書き方に意味が無かったため、実質的な影響は無いと
  考えられます）。詳しくは「[MMLの拡張](#mmlの拡張)」内の該当節を参照して
  ください。

さらに、オリジナル版のTODOリスト（[`org-doc/todo.txt`](../org-doc/todo.txt)）に
挙げられていた不具合のうち3件を修正しました。**いずれも、その不具合を踏んでいた
MMLの出力だけが変わります**（`M`コマンドと音長0の和音の併用、`=1`〜`=0`をまたいだ
テンポ設定、行中に書いた`=1`の後続トラックへの影響）。踏んでいなければ出力は
変わりません。詳しくは
「[不具合修正によって変わる挙動](#不具合修正によって変わる挙動)」を参照して
ください。

## MMLの拡張

### `Y` コマンド — モノモード切替

オリジナル版には無かった新規コマンドです。`Y` は、これまで未使用だった英大文字を
使い、GM/GS等で規定されているモノモード（コントロールチェンジ126番 Mono Mode On）
とポリモード（127番 Poly Mode On）の切り替えを1文字で書けるようにしたものです。

| 書き方 | 動作 |
| --- | --- |
| `Yn`（`n`は1〜127） | コントロールチェンジ126番（Mono Mode On） `n` を送出 |
| `Y0` | コントロールチェンジ127番（Poly Mode On） `0` を送出（モノモード解除） |
| `Y`（引数省略） | `Y1` と同じ |

```
A C1 @0 o4 l4
A Y   cdef        ; モノモード・オン（省略時は Y1 と同じ）
A Y0  cdef        ; ポリモードに戻す
A Y16 cdef        ; モノモード・オン（チャンネル数16）
```

- 引数は他のコマンドと同じ書き方が使えます。変数（`Yz3`）、16進（`Y0x10`）など。
- 0〜127以外を指定するとコンパイルエラーになります。
- 生のコントロールチェンジを送るオリジナル版からの `y` コマンド（小文字。
  `y126,1` のように書く）とは別のコマンドです。`Y` は `y126,n` /
  `y127,0` のよく使う組み合わせを短く書くための専用コマンドです。

### `@(msb,lsb,prog)` — バンクセレクト付きプログラムチェンジ

オリジナル版の `@n` はプログラムチェンジしか送出できず、バンクセレクトを併用する
には別途 `Hn1,n2` を書く必要がありました。本フォークでは `@` に括弧付きの書き方を
追加し、バンクセレクトとプログラムチェンジを1コマンドで書けるようにしました。

```
A C1 @(1,2,5)         ; H1,2 @5 と同じ
A C1 H1,2 @5           ; ↑と同じ内容を従来の書き方で
```

- 引数は3つとも省略できません。カンマの数や個数が合わないとコンパイルエラーに
  なります。
- 各引数は他のコマンドと同じ書き方が使えます。変数（`@(z0,z1,z2)`）、16進
  （`@(0x00,0x00,0x05)`）など。
- `@+n` / `@-n` で設定したオフセットは、`@(msb,lsb,prog)` の `prog` にも従来どおり
  適用されます。
- 従来の `@n` / `@+n` / `@-n` の意味は変わりません。`@(` は元の文法では
  コンパイルエラーだったため、この拡張によって解釈が変わる既存のMMLはありません。

### `P` / `X` コマンド — ペダル類のオン・オフ

オリジナル版の `P` / `X` はダンパー・ペダル（コントロールチェンジ64番）専用でした。
本フォークでは 0〜4 の引数を取れるようになり、他のペダル系コントロールチェンジも
扱えます。

| コマンド | 動作 | コントロールチェンジ |
| --- | --- | --- |
| `P0` / `X0` | ダンパー・ペダル　オン / オフ | 64 |
| `P1` / `X1` | ポルタメント　　　オン / オフ | 65 |
| `P2` / `X2` | ソステヌート　　　オン / オフ | 66 |
| `P3` / `X3` | ソフト・ペダル　　オン / オフ | 67 |
| `P4` / `X4` | レガート　　　　　オン / オフ | 68 |

- 引数を省略した `P` / `X` は **`P0` / `X0` と同じ**です。つまりオリジナル版と同じ
  ダンパー・ペダルのオン・オフになります。
- オンは値127、オフは値0を送出します。
- 引数は他のコマンドと同じ書き方が使えます。変数（`Pz3`）、16進（`P0x2`）、
  加減算（`P1+1`）など。
- 0〜4 以外を指定するとコンパイルエラーになります。

```
A C1 @0  o4 l4
A P  cdef X        ; ダンパー・ペダル（従来どおりの書き方）
A P0 cdef X0       ; 同上（明示的に書いた場合）
A P4 cdef X4       ; レガート・オン〜オフ
```

なお、ペダル系のコントロールチェンジは重複除去（同じ値の連続を省く最適化）の対象外
です。書いた回数だけそのままMIDIに出力されます。

### `#ampasandtie <on|off>` — `&` をタイ／スラー動作に切り替える

オリジナル版の `&` は「ノートオフを抑制して次の音を重ねる」ことで、1トラック内に
和音を作るための書き方でした（`c&e&g4` のように書くと、`c`,`e`,`g` が同時に
発音されたまま `g4` の音長が終わるまで待ち、その時点で3音まとめてノートオフされます。
`c0e0g4` と同じ結果になります）。他の多くのMML処理系では `&` はタイ／スラーとして
使われており、本ソフトにはこれまで同等の機能がありませんでした。

`#ampasandtie on` を指定すると、`&` の意味がタイ／スラーに切り替わります。

| 書き方 | `off`（既定値、従来どおり） | `on` |
| --- | --- | --- |
| `c&e&g4` | `c`,`e`,`g` を重ねて和音にする | `c`→`e`→`g` と順に鳴らし、レガートで繋ぐ |
| `c4&c4` | 同上（`c` を2回重ねて発音） | `c` の音長を合算した1つの音として鳴らす（タイ） |

`on` のときの `&` の動作は次のとおりです。

- **`&` の前後が同じ音高の場合**、音を再度鳴らし直さずに音長を合算します（タイ）。
  ノートオンは1回だけです。
- **`&` の前後が異なる音高の場合**、`&` で繋がれた一連のノート列の**先頭ノートの
  ノートオフの直前**にレガート・オン（コントロールチェンジ68番、`P4` と同じ）を、
  **末尾ノートのノートオフの直前**にレガート・オフ（同じくCC#68、`X4` と同じ）を
  挿入します。途中のノートは通常どおり個別にノートオン・ノートオフします。
  例えば `c&d&e&f&f&g&a` は、`f&f` が同音なので合算され、`c`,`d`,`e`,`f`,`g`,`a`
  の6音のスラーになります。最初の `c` のノートオフ前にレガート・オン、最後の `a`
  のノートオフ前にレガート・オフが入ります。
- **`&` に休符（`r` や `` \ ``）が挟まっている場合**、休符は「ノートオフを伴わない
  ステップ消費」として扱われます（音を鳴らしたまま時間だけ経過する）。音高の比較は
  休符を除いた前後の実音符同士で行います。`c&r&c` は同音として合算され、`c&r&d` は
  異音としてレガートの対象になります。チェーンの先頭が休符の場合（`r&c&d` など）は、
  最初の実音符の発音開始が単純に遅れるだけです。

```
#ampasandtie on
A C1 @0 o4 l4
A c&d&e&f&f&g&a    ; c-d-e-f(合算)-g-a のスラー
A c4&c4            ; cを合算した1音のタイ
```

- 既定値は `off`（従来どおりの和音動作）です。**`off` のままなら生成されるMIDIは
  一切変わりません。**
- `#german` や `#xtempo` と同じプリプロセス段階のディレクティブなので、ファイル中の
  どこに書いても、そのファイル全体（コンパイルされる全トラック）に対する一括切り替えに
  なります。書いた位置から後だけに効く、という指定はできません。
- `on` にする場合、和音を作る目的では従来どおり `c0e0g4`（音長0を使う書き方）を
  使ってください。この書き方は `&` を経由しないので、`on`/`off` どちらでも動作は
  変わりません。
- `on` の下で `&` チェーンの途中に `K`（Kコマンド）や `A`（ポリフォニックキー
  プレッシャー）が現れる書き方は未定義のためコンパイルエラーになります。
- `on` の下で、レガートの対象になる先頭または末尾のノートに負のローカル
  ゲートタイム（`,,-n`）を指定する書き方もコンパイルエラーになります。

これは、オリジナル版のTODOリスト（[`org-doc/todo.txt`](../org-doc/todo.txt)）に
挙げられていた「スラーコマンド．（ベンドをつかって音階を変化させる）」に相当する
機能です。ただし実現方法は異なり、ピッチベンドではなくレガート（CC#68）を使います。

### `~` によるノート連結 — 自動ポルタメント

音名を `~` で繋ぐと、`&` のタイ／スラー連結（前節参照）と同じ処理に加えて、
チェーンの境界にポルタメント・オン／オフ（コントロールチェンジ65番、`P1` /
`X1` と同じ）を挿入します。挿入位置はレガートと同じで、**先頭ノートの
ノートオフの直前**にオン、**末尾ノートのノートオフの直前**にオフです。

```
A C1 @0 o4 l4
A c~d~e~f    ; c-d-e-f をレガート+ポルタメントで繋ぐ
```

- `~` によるノート連結は `#ampasandtie` の on/off に関わらず常に有効です
  （前節の `&` チェーンとは異なり、この機能を使うのに `#ampasandtie on` を
  指定する必要はありません）。
- `&` と `~` は同じチェーンの中で混在できます（例: `c&d~e&f`）。この場合、
  チェーン全体が1つの連結として扱われ、レガートとポルタメントの両方が
  チェーン全体の先頭・末尾の境界に挿入されます（チェーンの中に `~` が
  1個でもあれば、チェーン全体にポルタメントが付きます）。
- 音高の合算・休符の扱い・`K`/`A` 禁止・負のローカルゲートタイム禁止は、
  前節の `&`（`#ampasandtie on`）チェーンと同じ規則です。
- `~` は元々 `BSn`（ベンド指定）の省略形として使われてきた文字です
  （`org-doc/command.txt` 参照）。**`~` の直後が音名として解釈できない場合
  （数字や `+`/`-` など）は、ノート連結ではなく従来どおり `BSn` の省略形として
  処理されます。** 例えば `c~64` は「note c」+「`BS64`」のままです。この
  判定は `~` 1文字だけでなく、その直後の1文字まで見て行われるため、既存の
  `~n` の使い方（音名の直後に書いた場合を含む）はすべてこれまでどおり
  コンパイルできます。

これは、オリジナル版のTODOリスト（[`org-doc/todo.txt`](../org-doc/todo.txt)）に
挙げられていた「ポルタメントコマンド（ベンドを使う）」に相当する機能です。
ただし実現方法は異なり、ピッチベンドではなくポルタメント（CC#65、および次節の
CC#84）を使います。

### `` `<音名> `` によるポルタメントソースノート指定

「1トラックでの和音演奏」節で説明した `` `<音名> ``（バッククォート付きの
音名）は、発音中の和音の中に一致する音が無い場合はエラーになります。ただし
**発音中の和音が一つも無い場合**（`c0e0...` のような和音がまだ一つも
開始されていない場合）に限り、エラーにする代わりに、コントロールチェンジ
84番（Portamento Control）でその音名をポルタメントのソースノートとして
指定します。ノートオンは生成しません。

```
A C1 @0 o4 l4
A `c d      ; CC84(60) を送ってから d を鳴らす(dはcからポルタメント)
```

- この用途では `` `<音名> `` を単体で書く必要があります。音長やカンマ引数
  （`` `c4 `` など）を付けるとコンパイルエラーになります。
- 発音中の和音はあるが指定した音高が和音の中に見つからない場合は、これまで
  どおりエラーになります（本節の対象は「和音が一つも無い」場合だけです）。

### トラック名 — 2文字目に数字を書けるようになりました

オリジナル版のトラック名は `A`〜`Z` の1文字だけで、主トラックは26本が上限でした。
本フォークでは2文字目に数字を付けられます。

| 書き方 | 意味 |
| --- | --- |
| `A` | 従来どおりの1文字のトラック名 |
| `A0` 〜 `A9` | 新しい2文字のトラック名。`A` とは**別のトラック** |
| `1A0` | トラック `A0` の従属トラック1 |

主トラックは 26 + 26×10 = **286本**まで書けます。従属トラックも従来どおり
`1`〜`9` を頭に付けられるので、トラックは最大 2860 本になります。

これは、オリジナル版のTODOリスト（[`org-doc/todo.txt`](../org-doc/todo.txt)）の
先頭に「トラック名を２文字でも指定可能に（メロディパートをMLと指定するとか）．
（2005/6/30）」として挙げられていた機能です。ただし2文字目に使えるのは数字だけで、
TODOの例にある `ML` のような英大文字2文字は採用していません。オリジナル版から
ある並列表記（`ML` ＝ トラック `M` と `L`）と区別できず、既存のMMLの解釈が
変わってしまうためです。

```
A  C1 o4 l4 cdef      ; 従来どおりのトラック A
A0 C2 o4 l4 efga      ; トラック A0（A とは別のトラック）
A1 C3 o4 l4 gab>c     ; トラック A1
1A0 C4 o5 l4 c        ; A0 の従属トラック1
```

トラック名の並び順（SMFに書かれる順番）は `A`, `A0`, `A1`, …, `A9`, `B`, `B0`, …
です。

**ワイルドカード `?` は桁ごとに展開されます。**

| 書き方 | 意味 |
| --- | --- |
| `?` | `A`〜`Z`（従来どおり。1文字のトラック名だけ） |
| `A?` | `A0`〜`A9` |
| `?0` | `A0`〜`Z0` |
| `??` | `A0`〜`Z9`（2文字のトラック名すべて） |
| `1??` | `1A0`〜`1Z9` |

2文字目の `?` は `0`〜`9` を表すので、`A?` に1文字のトラック名 `A` は**含まれません**。

**並列表記との関係。** オリジナル版から、トラック名は `AE`（＝ `A` と `E`）のように
並べて書けます。2文字目を足すとこれと紛らわしくなるため、**2文字目と見なすのは、
その次の文字が英大文字でも `?` でもない場合だけ**という規則にしました。これにより、
オリジナル版で書けた並列表記の意味は一つも変わりません。

| 書き方 | 意味 | 備考 |
| --- | --- | --- |
| `AE` | `A`, `E` | 従来どおり（`E` は数字でないので2文字目にならない） |
| `A1B` | `A`, `1B` | 従来どおり。`A1`, `B` にはならない |
| `?1?` | `A`〜`Z`, `1A`〜`1Z` | 従来どおり。`?1`, `?` にはならない |
| `1A2B` | `1A`, `2B` | 従来どおり |
| `A1` | `A1` | 次が行末なので2文字目になる |
| `A10B` | `A1`, `B` | 次が `0`（数字）なので `1` は2文字目になる |
| `A0B1` | `A`, `0B1` | 次が `B`（英大文字）なので `0` は2文字目にならない |

つまり、2文字のトラック名を並べて書くときは間に `0` を明示してください
（`A0` と `B1` の並列は `A00B1`）。1行に1トラックずつ書けば、この規則を意識する
必要はありません。

なお `??` は、オリジナル版では `?` を2回書いただけ（＝ `A`〜`Z`）でしたが、
本フォークでは2文字のトラック名すべてを表します。実用上、`??` を書く意味は
オリジナル版にはありませんでした。

### 出力できるトラック数の上限

オリジナル版の上限は64本（`too many tracks` エラー）で、しかもSMFヘッダのトラック数
を1バイトでしか書いていませんでした。本フォークでは16ビットで正しく書き出すように
し、上限をトラック名の組み合わせ数（2860本＋テンポマップの1本）まで引き上げました。
SMFの仕様上の上限は65535本です。

### 1トラックでの和音演奏 — 個別のノートオフと `r0`

オリジナル版には、音符の音長に `0` を指定すると「ノートオンだけ生成してステップを
進めない」という機能がすでにあります（`org-doc/mml2mid.txt` に記載）。これを使うと
`c0e0g4.` のように書くだけで、1トラック内に和音を作れます（`c`,`e` が発音された
まま `g4.` の音長が終わるまで待ち、その時点で3音まとめてノートオフされます）。

本フォークでは、この和音のうち**1音だけを個別に**ノートオフしたり、和音を
まとめて閉じる `r` に**発音区間を進めるだけ**の意味を持たせたりできるように、
バッククォート `` ` `` による新しい書き方を追加しました。

| 書き方 | 動作 |
| --- | --- |
| `` `<音名> ``（例: `` `e ``） | 発音中の和音のうち、指定した音階と一致する音を1つだけノートオフする |
| `` `<音名><音長> ``（例: `` `e4 ``） | 指定した音長分ステップを進めてから、その音をノートオフする |
| `r0` | 発音中の和音をまとめてノートオフする（ステップは進めない） |
| `` `r<音長> ``（例: `` `r4 ``） | 指定した音長分ステップを進めるだけで、ノートオフは一切しない |

```
A C1 @0 o4 l4
A c0e0g0          ; c,e,g を同時に発音（従来からある書き方）
A `e              ; e だけ先にノートオフ（c,g はまだ鳴っている）
A `r4             ; 4分音符分だけ経過させる（誰もノートオフしない）
A `c `g           ; 残りの c, g を個別にノートオフ
```

- `` `<音名> `` の音長を省略した場合は、他のコマンドと同じく `l` コマンドの現在値が
  使われます（省略時に「即座にノートオフ」にはなりません）。音名の前後の記法
  （`+`/`-`/`*` による臨時記号、オクターブ、`K`/`J` による強制転調など）は通常の
  音符と同じように働きます。
- `` `<音名> `` は、発音中の和音（`c0e0...` のように音長0や `&` で繋いでまだ
  ノートオフされていない音）の中に一致する音階が無いとエラーになります
  （後述のエラーメッセージ参照）。ただし**発音中の和音が一つも無い場合**は、
  エラーにする代わりにポルタメントソースノート指定として扱います（後述の
  「`` `<音名> `` によるポルタメントソースノート指定」参照）。
- `` `<音名> `` にカンマ区切りのベロシティ・ゲートタイム・キーオフベロシティの
  指定はできません（ノートオフ自体には意味が薄いため非対応です）。
- `r0` は、発音中の和音が無い場合は何もしません（オリジナル版と同じく無視されます。
  これは変わりません）。発音中の和音がある場合だけ、まとめてノートオフします。
- `` `r ``（バッククォート付きの `r`）は、通常の `r` が持つ「発音中の和音をまとめて
  閉じる」という自動的な動作を行いません。単純にステップを進めるだけです。

### `#sysexsinglequote <on|off>` — `EX` コマンド中の文字列埋め込みを `'...'` に切り替える

`EX`/`EE` コマンド中では、カンマの後ろに `"..."` と書くとその中身をASCIIバイト列
としてそのままSysExに埋め込めます（オリジナル版からある機能）。この文字列の中で
`"` そのものを書きたい場合は `\"` とエスケープする必要があります。

これは、機材が受け取るSysExの中身がJSONのような「`"` を大量に含むテキスト」の
場合に不便です（すべての `"` を `\"` に書き換える必要があるため）。
`#sysexsinglequote on` を指定すると、この文字列埋め込みの区切り文字が `"` から
`'` に切り替わり、`"` はただのデータとして無変換で埋め込めるようになります。

```
#sysexsinglequote on
; '{"key":"value"}' の中身がそのまま(エスケープ不要で)SysExに埋め込まれる
A EXx41,x10,x42,x12,{x40,x00,x7f,'{"key":"value"}'},xf7
```

上の例が出力するSysExは次のとおりです。

```
F0 41 10 42 12 40 00 7F 7B 22 6B 65 79 22 3A 22 76 61 6C 75 65 22 7D 21 F7
```

`7B`〜`7D` が `'{"key":"value"}'` の中身をそのまま並べたもの、続く `21` が
`{}` で囲んだ範囲（`40 00 7F` とこの文字列）に対する自動計算されたチェックサム、
末尾の `F7` が終端です。文字列の中の `{` `}` `,` は区切りとしては解釈されません
（チェックサムの計算対象にはなります）。

- 既定値は `off`（従来どおり `"..."` を使う）です。**`off` のままなら生成される
  MIDIは一切変わりません。**
- `on` のときは `'...'` を使います。`"` は区切り文字ではなくなるため無変換で
  埋め込めますが、`'` 自体を埋め込みたい場合はこれまでどおり `\'` とエスケープ
  してください（`\\` によるバックスラッシュのエスケープ、`\xHH` / 8進エスケープ、
  `'...'+'...'` による文字列連結も、区切り文字が変わるだけで従来と同じ書き方が
  使えます）。
- `on` のときは `"..."`（`off` のときの書き方）は使えなくなります。1つのファイル
  中で両方を混在させることはできません。
- `{}` によるチェックサム自動計算とは独立した機能なので、上の例のように
  `'...'` を `{}` の中に入れて組み合わせられます。チェックサムは閉じ括弧の
  **直後**に挿入されるので、終端の `xf7` は `{}` の外に書いてください。
- `#german` や `#ampasandtie` と同じプリプロセス段階のディレクティブなので、
  ファイル中のどこに書いても、そのファイル全体（コンパイルされる全トラック）に
  対する一括切り替えになります。書いた位置から後だけに効く、という指定は
  できません。ただし、行のコメント（`;` や `/* */`）を `'...'` の中身から除外する
  処理は行を読んだその場で行われるため、**`'...'` を使う行より前に
  `#sysexsinglequote on` を書いてください**（ファイルの先頭付近に書くのが
  安全です）。
- 埋め込む文字列は7bit ASCII範囲を想定しています。マルチバイト文字（Shift-JISの
  2バイト目など）をそのまま埋め込むと、その値がSysExの終端バイト（`0xf7`）などと
  衝突してMIDIメッセージ列が壊れる可能性があるため、避けてください。

### `mv` / `mt` コマンド — マスターボリューム／マスターファインチューン

現在未割り当てだった `m` を使い、GM2のユニバーサル・リアルタイムSysExを送出する
2つのコマンドを追加しました。

| コマンド | 動作 | 送出されるSysEx |
| --- | --- | --- |
| `mv0`〜`mv127` | マスターボリューム | `F0 7F 7F 04 01 ll mm F7`（`mm`=指定値, `ll`=0） |
| `mt-8192`〜`mt8191` | マスターファインチューン | `F0 7F 7F 04 03 ll mm F7`（14bit値 `ll mm` は指定値に `0x2000` を加算して0〜16383に正規化） |

```
A C1 mv100 mt1000
A cdefgab
```

- どちらも device ID には全デバイス宛の `0x7F` を使います。
- 引数を省略した場合、および範囲外の値を指定した場合はコンパイルエラーになります。
- `mv`/`mt` 以外の `m?` はコンパイルエラーになります。

このうち `mv` は、オリジナル版のTODOリスト
（[`org-doc/todo.txt`](../org-doc/todo.txt)）に挙げられていた「マスターボリューム
コマンドを付ける．」に相当する機能です（`mt` はTODOには無い追加分です）。

### `${名前}` — 長い名前のマクロ

オリジナル版のマクロは `$a`〜`$z` と `$0a`〜`$9z` の260個しかなく、名前に意味を
持たせられませんでした。本フォークでは、波括弧で囲んで**任意の長さの名前**を
付けられます。

```
${GM_RESET}     EXx7e,x7f,x09,x01,xf7
${MAIN_THEME}   l4 cde g2

A ${GM_RESET} r%24
A ${MAIN_THEME} ${MAIN_THEME}
```

名前に使えるのは英数字と `_` で、大文字小文字は区別されます。

- **定義は使用より後ろに書いてもかまいません。**マクロの中で別のマクロを使う
  場合も同じです（オリジナル版の `$a` は、マクロの中で使うマクロが先に定義されて
  いる必要がありました）。
- 同じ名前を2度定義してもエラーにはならず、後の定義が有効になります。
- オリジナル版と同じく、文字列（`"..."`）の中では展開されません。
- `${a}` のように旧方式と同じ形の名前（英小文字1字、または数字1字＋英小文字1字）は
  `$a` と同じものを指します。どちらの書き方でも同じマクロになるので、
  `$0a` で定義して `${0a}` で使う（またはその逆）ことができます。

### `${名前:引数1,引数2,…}` — 引数つきマクロ

マクロの本体に `#1`、`#2` … と書いておくと、呼び出し側で渡した引数がそこに
埋め込まれます。

```
${MIXER}  v#1 p#2 y91,#3 y93,#4

B @37 ${MIXER:120, 64, 30, 20}
C @31 ${MIXER:115, 64, 55,  0}
```

- 10個目以降の引数は `#{10}` のように番号を `{ }` で囲んでください。`#10` だと
  「1番目の引数に `0` を繋げたもの」と解釈されます。
- 引数に `,` そのものを含めたい場合は `\,` と書いてください。`\` を含めたい場合は
  `\\` です。ただし `{ }` で囲んだ部分の中の `,` は区切りと見なされないので、
  `${a:{x40,x01,x30,x00}}` のようにそのまま書けます。
- 引数の個数は検査しません。足りない分は空文字列に、余った分は捨てられます。
- 引数つきマクロを呼び出すときは、名前が短くても必ず `{ }` で囲んでください
  （`$a:x,y` とは書けません）。定義行の方は `$a cde#1#2` と書いてもかまいません。
- 文字列（`"..."`）の中の `#1` は置換されません。

なお `${名前}` と `${名前:…}` は、この2つを合わせてオリジナル版のTODOリスト
（[`org-doc/todo.txt`](../org-doc/todo.txt)）の
「`#define`コマンドをつける．（長いマクロ名＋変数）」に相当する機能です。

### `i` / `j` — 半音数からピッチベンド値を算出する

`~`（`BS`）や `FB` / `UB` に渡すピッチベンド値を、生の数値ではなく**半音単位**で
書けます。`i` は `~` / `BS` 用の 0〜127 を、`j` は `FB` / `UB` 用の -64〜63 を
返します。

```
#bendrange 8

A BR8
A l4 c&~i2r ~i0            ; c から2半音上(＝d)へスラー、そして元に戻す
A FB1, 0, 4,j-2 a4 FB0     ; a から2半音下(＝g)へ4分音符かけて滑らかに下げる
```

- 符号は `i-2` のように**文字の後ろ**に書きます。
- 基準となるベンドレンジは後述の `#bendrange` で指定します（既定は2）。
  この機能を使うトラックは、`BR` で同じ値を設定しておく必要があります。
- ベンドレンジを超える半音数を指定した場合は、エラーにせず 0〜127 の範囲に
  収めます。ベンドレンジで割り切れない半音数は正確な音程になりません。
- 数値を取るコマンドの引数解析に組み込んであるので、`v` や `y` など数値を取る
  コマンドならどこでも同じ記法が使えます。`i2+3` のような加減算の連結も従来どおり
  効きます。
- `BW`（0〜16383）用の値を算出する機能はありません。

### `#bendrange <1〜24>` — `i` / `j` の基準ベンドレンジ

`i` / `j` が半音数をピッチベンド値に換算するときの基準です。省略時は 2。

```
#bendrange 8
```

- `#german` などと同じプリプロセス段階のディレクティブなので、ファイル中の
  どこに書いてもファイル全体に効きます。
- 互換のため、マクロ `${_bend_range_}` に数値を定義しても同じ意味になります
  （後述の mmlpp 互換）。両方書いた場合は `#bendrange` が優先されます。

### 外部プリプロセッサ mmlpp について

上の4つ（`${名前}`、`${名前:引数}`、`i`/`j`、ベンドレンジ指定）は、オリジナル
配布物に同梱されている外部プリプロセッサ **mmlpp**（[`mmlpp/mmlpp.pl`](../mmlpp/mmlpp.pl)、
新出尚之氏作。`i`/`j` はメモル（吉村隆則）氏による追加）が持っていた機能を
本体に取り込んだものです。**mmlpp 向けに書かれたMMLは、`perl mmlpp.pl` を
通さずにそのままコンパイルできます。**

mmlpp との差が残るのは1点だけです。mmlpp は全マクロをテキストとして先に展開する
ため、マクロの中の `[ ]` ループが自己完結していなくてもかまいませんでした
（[`mmlpp/mmlppdoc.txt`](../mmlpp/mmlppdoc.txt)〔1.5〕[c]）。本フォークでは
**長い名前のマクロだけ**がその挙動になり、旧方式と同じ形の名前
（`$a` / `${a}` / `$0a` / `${0a}`）はオリジナル版どおり定義時にループを展開します。

```
${LOOP} [cde]
A ${LOOP}4     ; 「[cde]4」＝ cde を4回。mmlpp と同じ

$a [cde]
A $a4          ; 「cdecde4」。オリジナル版と同じ（mmlpp では「[cde]4」）
```

`mmlpp/` はオリジナル配布物の一部としてそのまま残してありますが、本フォークでは
通常使う必要はありません。

## エラーメッセージの追加

オリジナル版には無かったエラーメッセージが12個あります。`pedal` と `exclusive` の
2つは、オリジナル版ではエラーにならずに壊れた動作をしていたケースを正しく検出する
ようにしたものです。残る10個（`@(?,?,?)`、`Y?`、`` `? ``、`&`/`~`のチェーン関連2つ、
ポルタメントソースノート関連1つ、`m?`/`mv?`/`mt?` の3つ、`i?`/`j?`）は、本フォークで
追加した新規構文自体のチェックです。

| メッセージ | 意味 |
| --- | --- |
| `pedal 'P?' or 'X?' is wrong` | `P` / `X` の引数が 0〜4 の範囲外です |
| `exclusive data too long` | `EX` / `EE` のデータが長すぎます（後述） |
| `program change '@(?,?,?)' is wrong` | `@(msb,lsb,prog)` の書き方が誤っています |
| `mono mode 'Y?' is wrong` | `Y` の引数が 0〜127 の範囲外です |
| `backquote note off '`?' has no matching sounding note` | `` `<音名> `` に対応する発音中の音が無い(発音中の和音自体はある場合) |
| `'&'/'~' chain cannot contain 'K' or 'A'` | `&`/`~` チェーンの途中に `K`/`A` が現れた |
| `'&'/'~' chain boundary cannot use a negative local gatetime` | レガート/ポルタメント境界のノートに負のローカルゲートタイムを指定した |
| `` backquote portamento source note '`?' cannot take a length or comma argument `` | ポルタメントソースノート指定（発音中の和音が無い場合の `` `<音名> ``）に音長やカンマ引数を付けた |
| `no such a command 'm?'` | `m` の次の文字が `v`/`t` 以外です |
| `master volume 'mv?' is wrong` | `mv` の引数が省略された、または 0〜127 の範囲外です |
| `master fine tune 'mt?' is wrong` | `mt` の引数が省略された、または -8192〜8191 の範囲外です |
| `bend value 'i?' or 'j?' is wrong` | `i` / `j` の後ろに半音数の数字がありません |

マクロ展開（`${…}`）のエラーは、`#include` や注釈と同じプリプロセス段階で起きる
ため、上の表とは別に「エラー内容 in line 行番号. &lt;ファイル名&gt;」という形式で
報告されます。`undefined macro '${…}'`（未定義のマクロを使った）、
`macro argument list not closed`（`}` が無い）、
`macro expansion too deep (recursive macro?)`（マクロが自分自身を呼んでいる）、
`illegal macro reference '${...}'`、`macro name is empty` の5種類です。

## 不具合修正によって変わる挙動

オリジナル版のバグを直した結果、ユーザーから見て動作が変わる箇所です。

### モダナイズの過程で見つけた不具合の修正

- **同じ行で主トラックより後ろに書いた従属トラックが無視されなくなりました。**
  **生成されるMIDIが変わります**。オリジナル版は、どのトラックが存在
  するかを調べる処理が主トラックを見つけた時点で行の残りを読むのをやめていたため、
  `A1A ...`（トラック `A` と、その従属トラック `1A` に同じMMLを書く指定）と書くと
  `1A` が黙って捨てられていました。同じ行でも主トラックより前に書いた場合
  （`1AA ...`）は正しく動いていたので、一貫していませんでした。現在はどちらでも
  `1A` が出力されます。ワイルドカードを使った `0?2?` のような指定でも同じ問題が
  ありました。

### オリジナル版のTODOリストにあった不具合の修正

[`org-doc/todo.txt`](../org-doc/todo.txt) の「以下のバグを直す．」に挙げられて
いた項目のうち3件です。いずれも**その不具合を踏んでいたMMLの出力だけ**が
変わります。

- **`M1,50 c0e2` のようにMコマンドと音長0の和音を併用してもモジュレーションが
  かかるようになりました。** 音長0の音符（`c0e0g4.` のように書く和音の先頭）は
  ステップを1つも消費しないため発音窓が0になり、「ディレイがこの音符に収まるか」
  の判定が必ず外れて、遅延モジュレーションが永久に発行されませんでした。判定は、
  実際に長さを持つ次の音符まで持ち越すようにしました。
  `M1,50 c&e2` のように先頭が長さを持つ場合の動作は変わりません。ディレイが
  和音全体の長さを超える場合に発行しない、という従来の動作も変わりません。

- **`=1`〜`=0` で飛ばした区間のテンポが、再開後のテンポを上書きしなくなりました。**
  飛ばした区間で設定されたテンポは `=0` の時点で反映されるべきものですが、
  テンポマップはトラック単位に順に積まれるため、ステップタイムが同じだと
  トラックの並び順で後勝ちになっていました。テンポ命令を書いたトラックと、
  再開後にテンポを設定し直したトラックが違うと、後者が無効になります
  （TODOリストの例そのままです）。同じステップタイムでは `=` をまたいだ順序を
  トラックの並び順より優先するようにしました。**`=` を一切使っていないMMLでは
  順序付けは従来どおりで、出力は1バイトも変わりません。**

- **行の中に `=1` を書いたトラックが、後続のトラックに影響しなくなりました。**
  「`=1` があったかどうか」のフラグがトラックごとに初期化されておらず、行の中に
  `=1` を書いたまま終わったトラックのフラグが次のトラックへ持ち越されていました。
  その結果、`=1` を一度も通っていないトラックが `=0` の行でバンクセレクトと
  プログラムチェンジ（およびモジュレーション・ボリューム・パンポット・
  エクスプレッション・チャンネルプレッシャー）を余計に出力していました。

なお、TODOリストの残りの項目（従属トラックが主トラックの複数行にまたがる
繰り返しを追わない、`=0` をはさむと `^n` が休符になる、`=1` 区間で設定した
NRPN・ディチューン・ベンドレンジ等が `=0` で復帰しない）は未修正です。

### その他

- **`EX` / `EE` が長すぎる場合。** オリジナル版は境界チェックをしておらず、長い
  エクスクルーシブを書くとスタックを破壊して異常終了（あるいは無関係な誤動作）を
  起こしていました。現在は `exclusive data too long` エラーで正しく停止します。
- **`kr1`（または `kr n,0`）でクラッシュしなくなりました。** オリジナル版はゼロ除算で
  異常終了していました。
- **`S` コマンドを多用したトラックでクラッシュしなくなりました。** 進捗表示用の
  8KB固定バッファが溢れていたものです。
- **`#title` / `#copyright` が256バイトの場合。** オリジナル版は長さ0として書き出す
  ため壊れたメタイベントになっていました。現在は255バイトまでを上限としてエラーに
  します。
- **パイプからの入力が動くようになりました。** `cat foo.mml | mml2mid - foo.mid`
  のような使い方が、オリジナル版では空入力になっていました。

「その他」の各件は、正常なMMLをコンパイルした場合の出力には影響しません。
出力が変わりうるのは、その前の2つの節に挙げた4件（従属トラック、および
TODOリスト由来の3件）だけです。

## 対応環境とビルド方法

| 項目 | オリジナル版 | 本フォーク |
| --- | --- | --- |
| 対応環境 | MS-DOS / Win16 / Win32 / UNIX（32bit） | Windows / Linux / macOS（**64bit**） |
| ビルド | 環境ごとの `makefile.bcc` / `.egc` / `.lcc` を選択 | `CMakeLists.txt` または `src/makefile` の一本化。設定用スイッチ不要 |
| 同梱バイナリ | DOS版・Win32版の `.exe` を同梱 | 同梱せず（ソースからビルド） |

- Win64では、オリジナル版のファイル位置計算が `long`（32bit）で切り詰められており、
  そもそも正しく動作しませんでした。これが64bit化の主眼です。
- MS-DOS版・Win16 GUI版のコードは削除しました。これらの環境向けにビルドすることは
  できません。
- 詳細は [BUILD.md](../BUILD.md) を参照してください。

## 文字コード

オリジナル配布物は全体がEUC-JPでした。本フォークではソースとドキュメントをUTF-8に
変換していますが、**コンパイラへの入力データは元のまま**です。

| 対象 | 文字コード |
| --- | --- |
| ドキュメント（`org-doc/*.txt`、`doc/*.md`、`src/mml2mid.1`） | UTF-8 |
| `org-doc/tr-rack.mml` | **EUC-JP のまま** |
| `org-doc/mml2mid.def` | 変更なし（VZエディタ用、バイナリを含む） |

`.mml` はドキュメントではなくコンパイラへの入力データです。mml2mid は文字列中の
バイトをそのままSMFのメタイベント（曲名・トラック名など）へ書き出すため、`.mml` の
文字コードを変えると**生成されるMIDIの中身が変わります**。自分のMMLで日本語を使う
場合は、従来どおり `-m` オプション（文字列中をShift-JISとみなす）で使い分けてください。

## 配布物の構成

### サンプル曲（`sample/`）は同梱していません

オリジナル配布物に含まれていたサンプル曲は、**本フォークでは再配布していません。**
各曲の著作権はそれぞれの作曲者に帰属する第三者の著作物で、自由利用が明示されて
いるのは門田氏作の曲のみだからです。

回帰テストを実行する場合は、
[オリジナル配布物](https://www.vector.co.jp/soft/dl/unix/art/se102432.html)の
`sample/` ディレクトリをツリー直下にコピーしてください。無い場合はテストが無効に
なるだけで、ビルドは正常に行えます。詳細は
[test/README.md](../test/README.md) を参照してください。

### ドキュメントの配置

オリジナル版の `doc/` は `org-doc/` にリネームし、本フォークで書いたドキュメントを
新しい `doc/` に置いています。

| パス | 内容 |
| --- | --- |
| `org-doc/` | **オリジナル配布物のドキュメント**（MMLリファレンス、テクニック集など。内容はそのまま） |
| `doc/` | 本フォークのドキュメント（このファイルと [STATUS.md](STATUS.md)） |
| `test/` | 回帰テスト用のベースライン・トラック名テスト・スクリプト（本フォークで追加） |
| `cmake/` | ctest から呼ばれるテスト実行スクリプト（本フォークで追加） |

`org-doc/` 内の記述は**オリジナル版時点のもの**です。`org-doc/mml2mid.txt` や
`org-doc/command.txt` の `P` / `X` の説明は引数なしのまま、`org-doc/mml2mid.txt`
「3.4.1 トラック名」も1文字のトラック名のままなので、上記
「[MMLの拡張](#mmlの拡張)」で読み替えてください。
[readme.txt](../org-doc/readme.txt) と `org-doc/chnglog.txt` も同様に、オリジナル配布物の
内容をそのまま残しています。

[`org-doc/todo.txt`](../org-doc/todo.txt) だけは配布物には含まれておらず、作者の
Webページ `http://hpc.jp/~mml2mid/todo.html`（現在はアクセス不可。Internet Archive
の2023-05-31保存分）にあった「今後実現しようと思っていること」の一覧を、
ISO-2022-JPからUTF-8に変換してプレーンテキスト化したものです。本文は原文のままで、
上記の「[MMLの拡張](#mmlの拡張)」のうちいくつかはこのTODOに挙げられていた項目に
対応しています（各節に明記しました）。
