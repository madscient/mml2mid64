## サンプル曲の削除と非公式フォークであることの明示

`sample/` を削除。各曲の著作権はそれぞれの作曲者に帰属する第三者の著作物であり、
自由利用が明示されているのは門田氏作の曲のみのため、再配布しないことにした。

オリジナルのライセンス（`org-doc/copyrigh.txt` と `header.txt`）で明示されている
のは「転載可」「フリーソフト＝無料」「無保証」のみで、**改変版の再配布は許諾されて
いない**。このためMIT等での再ライセンスもできない（サブライセンス権がないため）。
README にこの点と、本フォークが非公式・無認可であることを明記した。

付随する対応:

- サンプル曲が無い場合、CMake はその旨を表示してテストを無効化する（ビルドは正常）。
- `test/baseline.sha256` と `test/run-baseline.sh` は残置。オリジナル配布物の
  `sample/` をツリー直下に置けばそのまま検証できる。
- `test/README.md` に入手方法を記載。

**注意:** git履歴には削除前の `sample/` が残っているため、公開リポジトリから完全に
除去するには履歴の書き換え（`git filter-repo` 等）とforce pushが必要。

### 1トラック和音演奏の拡張 — 個別ノートオフと`r0`（2026-08-06）

オリジナル版にすでにある「音長0の音符はノートオンだけ生成してステップを進めない」
機能（`c0e0g4.` で1トラックに和音を書ける、Ver5.09で追加・`org-doc/mml2mid.txt`に
記載）を使って、和音の一部だけを個別にノートオフできるようにしたいという要望が
あった。仕様は [CHANGES.md](CHANGES.md#mmlの拡張) を参照。

**衝突の検討。** 実装前に、既存の文法との衝突を調査した。

- バッククォート `` ` ``(0x60) は、字句レベル（`src/charproc.c` の `track()` /
  `macro()` トークナイザが特殊扱いするのは `[ ] / : $ " スペース タブ |` のみ）
  でもコマンドレベル（`do_command()` のswitchに該当ケースが無く、現状は
  `default: syn_err` に落ちる。`escchr()` にも未登録）でも完全に未使用だった
  （`grep -rn '\`' src/` で確認）。新しいプレフィックスとして安全に導入できる。
- 音名(`a`〜`h`)・`l` コマンドの音長0は、要求された時点で**既に実装済み**
  だった（[note.c](../src/note.c) の「音長ゼロの音符」ブロック、Ver5.09で
  `l0`/`l%0` も許可済み）。休符(`r`)だけが例外で、`r0` は
  `if((local.oto & OTO_KYUFU) && local.oncho == 0) return;` により常に
  無視される仕様だった。これは Ver5.02 で「音長ゼロの休符があると変な動作を
  するのを修正した」というバグ修正由来のガードで
  （`org-doc/chnglog.txt`）、`r0`を「発音中の和音をノートオフする」に
  変えるのは、この無視という仕様そのものを変更する後方非互換な変更になる。
  サンプルMML(`.orig-sample/`)に `r0` の実使用は見つからなかった。
- 「発音中のノート」をエンジンが一元的に持つレジストリは無く、実体は
  `keyproc[]`（音長0や`&`で繋いだ、次の非タイ音符/休符でまとめてノートオフ
  される音の配列）と `keyproc2[]`（負のゲートタイムで将来ノートオフ予定の
  音の配列、別機能）の2つのみ。和音記法が使っているのは前者なので、
  `r0` や `` `<音名> `` の対象は `keyproc[]` に限定することにした
  （ユーザーに確認済み）。
- `` `<音名> `` で音長を省略した場合のデフォルトを検討した。既存の全コマンド
  （音名・`r`・`l`）は「省略時は`l`コマンドの現在値を採用」という規約なので、
  ここでもそれに合わせることにした（ユーザーに確認済み）。「省略時は即座に
  ノートオフ」という特別扱いは既存の規約と矛盾するため採用しなかった。

**実装** ([`src/note.c`](../src/note.c), [`src/mmlproc.c`](../src/mmlproc.c)):

- `get_note_values()` 内の音階計算（オクターブ・臨時記号・移調・強制転調）を
  `compute_onkai()` として切り出した。`` `<音名> `` からも同じ計算を使うため。
- `r0` のガードを `keyproc_ptr == 0` の場合だけ無視するように変更。
  `keyproc_ptr != 0` のときは既存の「音長ゼロの音符」ショートカットを
  素通りして（このブロックに休符除外の条件を追加）、下のキーオフ処理まで
  そのまま進む。休符は `local.gatetime` が常に0になる既存の規約により、
  そこは「即時キーオフ」分岐（`keyproc[]`を全件ノートオフする既存の経路）に
  自然に入る。新規ロジックはほぼ無く、ガード条件2箇所の変更のみ。
- `note()` を薄いラッパーにし、実体を `note_impl(code, no_flush)` に分離。
  `` `r `` 用の `note_r_noflush()` は `note_impl('r', 1)` を呼ぶだけ。
  キーオフ処理セクション冒頭の条件を
  `if(!(local.oto & OTO_KYUFU) || (keyproc_ptr != 0 && !no_flush))` に変更し、
  `no_flush` が真のときは強制的に「単なる休符」分岐（ステップを進めるだけで
  ノートオフを一切しない、既存の経路）に入るようにした。F/I/M・
  `keyproc2`・`psw`・ランニングステータス等はすべて既存のまま自動的に効く。
- `` `<音名> `` 用に `note_off_specific()` を新設。`compute_onkai()` で
  対象ピッチを求め、`length()` で音長を解決し（省略時は`l`値、既存と同じ
  規約）、音長分だけ「単なる休符」と同じ手順（`tstep`/`lastlenpos` の
  巻き戻しトリック→ステップ0で確定しているmmlprocだけ即時消化→
  `write_length`）でステップを進めてから、`keyproc[]` を先頭から線形探索して
  一致するエントリを1つだけ `noteoff()` し、`shift_array` マクロ（既存）で
  配列から除去する。一致が無ければ新エラー75番。`andflag`/`preandflag` には
  触れない（和音構築中のタイ連鎖の状態を乱さないため）。
- `do_command()` の switch に `` ` `` を追加。`case 'h':` と同じ流儀で次の
  1文字を読み、`a`〜`g`・(german_scaleなら)`h` は `note_off_specific()`、
  `r` は `note_r_noflush()` に振り分ける。無効な文字は実際に問題の文字を
  `code` に代入してから既存の `syn_err` に合流させる。
- `err_msgs[]` に75番
  `"backquote note off '`?' has no matching sounding note"` を追加。

**既知の限度。** トラック終端で `keyproc[]` に閉じられていないエントリが
残っていても、現状は何もノートオフされない（`write_keyproc2()` /
`write_restofmmlproc()` は `keyproc2[]` / `mmlproc[]` しか見ていない）。
これは今回の変更以前から存在する挙動で、今回のスコープでは修正していない。

### `Y` コマンドの追加（2026-08-06）

未使用だった英大文字 `Y` に、モノモード切替の専用コマンドを割り当てた。仕様は
[CHANGES.md](CHANGES.md#mmlの拡張) を参照。

- `Yn`（`n`=0〜127、省略時1）でコントロールチェンジ126番（Mono Mode On） `n` を
  送出する。ただし `n=0` の場合だけ例外的にコントロールチェンジ127番
  （Poly Mode On） `0` を送出する（モノモード解除は127番を送るのがGM/GS等の作法
  のため）。
- 既存の `y`（小文字）コマンドは任意のコントロールチェンジを2引数で直書きする
  汎用コマンドで、これを使えば `y126,1` / `y127,0` として同じ結果を得られる。
  `Y` はこの2つの組み合わせのショートハンド。

**衝突の検討。** `do_command()` の `switch` に大文字 `Y` を処理する `case` は無く、
`Y` は他のどのコマンドにも使われていなかった（`grep -rn "'Y'" src/` で確認）。
トラック名の1文字目としては `A`〜`Z` すべてが使えるが、これは行頭でのトラック
選択という別の文法要素であり、`do_command()` はトラックのMML本体を読んでいる間
だけ呼ばれるので衝突しない（`H`, `M`, `D` など他の大文字コマンドと同じ関係）。

実装（[`src/mmlproc.c`](../src/mmlproc.c)）:

- `do_command()` に `case 'Y': code_Y(); break;` を追加。
- `code_Y()` を新設。`xget()` で引数を読み、省略時（`i == -2`）は1を補う。
  0〜127の範囲外は新エラー74番。`n == 0` なら `put_cntchange(127, 0, 0)`、
  それ以外は `put_cntchange(126, num, 0)` を呼ぶ。`P`/`X` コマンドの `pedal()` と
  同じ構成。
- `err_msgs[]` に74番 `"mono mode 'Y?' is wrong"` を追加。

確認したこと:

- `Y`（引数省略）が `b0 7e 01`（CC126, 1）を出力すること。
- `Y0` が `b0 7f 00`（CC127, 0）を出力すること。
- `Y64` が `b0 7e 40`、`Y127` が `b0 7e 7f` を出力すること。
- `Y128` が新エラー74番で停止すること（終了コード1）。
- `ctest -C Release` が 7/7 合格すること（サンプル曲は非同梱のため未実行）。

### `@(msb,lsb,prog)` コマンドの追加（2026-08-06）

`@` にバンクセレクト付きプログラムチェンジの括弧記法を追加した。仕様は
[CHANGES.md](CHANGES.md#mmlの拡張) を参照。

**衝突・後方互換性の検討。** `@` の後続文字を決める `xget()` は、認識できない
文字（`(` を含む）に遭遇すると、その文字を消費せずに `i = -2` を返す
（[`src/mmlproc.c`](../src/mmlproc.c) の `xget()` の `default:` 節）。
このため `@(` は拡張前から `mml_err(23)` で止まる文法エラーであり、この拡張が
意味を変える既存のMMLは存在しない。`(` / `)` はトップレベルではベロシティ
昇降コマンド（`case '(': kakko2();` / `case ')': kakko1();`）だが、これは
`do_command()` が新しいコマンド文字を読む瞬間にのみ関係する。`t(` / `t)`
（テンポスタックの push/pop）が既に同じ手法で `(` / `)` を先読み・消費してから
サブ文法に入っており、`progchange()` 内で `getbyte(1)` により `(` を先読みして
消費すれば、外側のディスパッチループに `(` が渡ることはなく衝突しない。

実装（[`src/mmlproc.c`](../src/mmlproc.c)）:

- `progchange()` の先頭で `getbyte(1) == '('` を先読み。真なら `xget()` →
  `,` → `xget()` → `,` → `xget()` → `)` の順にMSB・LSB・プログラム番号を読み、
  誤りがあれば新エラー73番で停止する。引数の解析はすべて `xget()` に任せている
  ので、変数・16進・加減算の記法がそのまま使える。
- バンクセレクトは既存の `H` コマンド（`bankselect()`）と同じ `bs1` / `bs2` を
  更新し、`put_cntchange0(0, bs1)` / `put_cntchange0(32, bs2)` で送出する。これに
  より、`=` スイッチ（`setpsw()`）がプログラムチェンジ再送時に読む `bs1` / `bs2`
  とも整合する。
- プログラムチェンジ本体の送出は `put_progchange()` として切り出し、従来の
  `@n` 経路と `@(...)` 経路の両方から呼ぶ（重複コード排除）。
- `prog` には従来どおり `base`（`@+n` / `@-n` で設定）を加算するので、
  `@(msb,lsb,prog)` の `prog` にもオフセットが効く。
- `err_msgs[]` に73番 `"program change '@(?,?,?)' is wrong"` を追加。

確認したこと:

- `@(1,2,5)` と `H1,2 @5` をそれぞれコンパイルし、生成されるバイト列
  （`b0 00 01 00 20 02 00 c0 05`）が完全一致することを確認。
- `@+3 @(1,2,2)` が `@+3 @2` と同じ `c0 05` になり、`base` オフセットが括弧内の
  `prog` にも適用されることを確認。
- 引数不足（`@(1,2)`）・閉じ括弧なし（`@(1,2,3`）がいずれも新エラー73番で
  停止すること（終了コード1）を確認。
- `ctest -C Release` が 7/7 合格すること（サンプル曲は非同梱のため未実行）。
  従来の `@n` / `@+n` / `@-n` の経路は分岐前と同一のコードのままなので、
  既存サンプルの生成MIDIへの影響はない。

### トラック名の2文字化（2026-08-06）

トラック名を `[A-Z]` から `[A-Z][0-9]?` に拡張し、主トラックを26本から286本に
増やした。仕様は [CHANGES.md](CHANGES.md#トラック名--2文字目に数字を書けるようになりました)
を参照。

**2文字目を数字に限った理由。** 当初の案は `[A-Z][0-9A-Z]` だったが、これは
オリジナル版の並列表記（`AE` ＝ トラック `A` と `E`）と衝突して解決できない。
2文字目を数字に限ると、衝突するのは「英大文字＋数字」と「英大文字＋従属トラック
番号＋英大文字」の間だけになり、次の1文字を先読みすれば区別できる。

**曖昧性の解決規則.** 数字（あるいは `?`）を2文字目と見なすのは、その次の文字が
英大文字でも `?` でもない場合だけ。そうでなければ次のトラック指定の先頭と見なす。
この規則により `A1B`（＝ `0A`, `1B`）や `?1?`（＝ `0A`-`0Z`, `1A`-`1Z`）といった
オリジナル版の並列表記の意味が一つも変わらない。

実装:

- [`src/charproc.h`](../src/charproc.h) — トラック名を通し番号 `talf` に符号化する
  マクロ群を新設。`talf = (1文字目 - 'A') * TRK_SUFFIXES + 2文字目コード`、
  2文字目コードは無しが0で `'0'`〜`'9'` が1〜10。`talf == 0` が従来どおり
  トラック `A` になるので、`talf` を0から回す既存のループがそのまま使える。
- [`src/charproc.c`](../src/charproc.c) — `getsuffix()` を新設（2文字目の読み取りと
  上記の先読み）。`gettrack()` はこれを呼び、`talf` を1文字目・2文字目に分解して
  照合するようにした。あわせて、一致しなかった `?` で行の残りの並列指定を捨てて
  しまわないよう、内側ループの脱出条件を `!is_upper(i2)` から
  `!(is_upper(i2) || i2 == '?')` に変更（`?` は2文字目のせいで一致しないことが
  あるため。1文字名しかなかった頃は `?` は必ず一致していたので影響はない）。
- [`src/charproc.c`](../src/charproc.c) — トラックマップの作成を、`gettrack2()` に
  よる「トラック名1個につきファイル全走査」から、`build_track_map()` による
  **1回の走査**に置き換えた。トラック名が26通りから286通りに増えるため、
  従来方式では走査回数が11倍になる。`analyze()` から明示的に呼ぶ。
- [`src/mml2mid.c`](../src/mml2mid.c) — `track_map[]` を `TRKMAP_SIZE` に拡大
  （添字の刻みを32から `TRKMAP_STRIDE` へ）。`talf` のループを `NTRKNAME` まで回す。
- [`src/mmlproc.c`](../src/mmlproc.c) — 進捗表示の `trk %d%c` を
  `trk %d%s` + `trkname_str()` に変更。

**トラック数の上限**（`MAXTRKNUM`）を64から `10 * NTRKNAME + 1`（2861）にした。
あわせて `smfheader()` がSMFヘッダのトラック数を1バイトでしか書いていなかったのを
16ビットで書くように修正（従来は上位バイトに0を書きっぱなしだった）。64本以下では
出力バイト列は変わらない。`format1to0()` の `ctrk[]` / `endsw[]` は要素数が増えた
ので `static` にしてスタックから外した。

**副作用の不具合修正。** トラックマップを1回の走査で作るようにしたことで、
オリジナル版の遅延作成が持っていたバグが直った。従来は、主トラックを見つけた時点で
その行の残りを読むのをやめていたため、`A1A` のように主トラックより後ろに書いた

  代替した。`sample/` を持ち込める環境では別途確認が必要。

トラック名の文法を固定する `ctest` のテストスイートを新設した

`.mml` ごとに、出力されるべきトラック名を出力順に並べた `.trk` を置き、標準エラーの

### `P` / `X` コマンドの拡張（2026-08-06）

`P` / `X` が 0〜4 の引数を取れるようにし、ダンパー・ペダル以外のペダル系
コントロールチェンジ（65〜68番）にも対応した。仕様は
[CHANGES.md](CHANGES.md#mmlの拡張) を参照。

実装（[`src/mmlproc.c`](../src/mmlproc.c)）:

- `pedal(int on)` を新設。引数を `xget()` で取り（省略時は0）、範囲外なら新エラー
  72番でエラーとし、`put_cntchange(64 + n, on, 0)` を出力する。
  引数の解析を `xget()` に任せているので、変数・16進・加減算の記法がそのまま使える。
- `mmlcmd()` の `case 'P'` / `case 'X'` を `pedal(127)` / `pedal(0)` に置き換え。
- `err_msgs[]` に 72番 `"pedal 'P?' or 'X?' is wrong"` を追加。

確認したこと:

- `P`, `X`, `P0`〜`P4`, `X0`〜`X4` の12通りをコンパイルし、出力が
  CC64=127 / CC64=0 / …… / CC68=127 / CC68=0 になることをバイト列で確認。
- `P5` と `X-1` が新エラーで停止すること（終了コード1）。
- `ctest -C Release` が 33/33 合格すること。引数なしの `P` / `X` は従来どおり
  CC64 なので、既存サンプルの生成MIDIは不変。

`README.md` と `BUILD.md` に、本ツリーが mml2mid 5.30b のフォークである旨、

### `2841323` — 初期コミット（64bit化）

ビルドシステム:

- `CMakeLists.txt`（MSVC / GCC / Clang対応）を追加。`src/makefile` を
  `install` / `check` ターゲットを持つ移植性のあるMakefileに書き直し。
- `-DUNIX` を廃止し、`_WIN32` の有無でプラットフォームを判別。
- 旧来の `makefile.bcc` / `makefile.egc` / `makefile.lcc` および `file.asm`
  （16bit DOS用アセンブラ）はどのビルドからも参照されない。

64bit対応:

- `Fpos_t` が `long` だった。ファイル位置はポインタ同士の差から計算されるため、
  `long` が32bitであるWin64では算出された位置が毎回切り詰められていた。
  `ptrdiff_t` に変更し、`fseek2` / `ftell2` / `smftrkend` も追随。
- `qsort()` にプロトタイプなし関数ポインタ型へキャストした比較関数を渡していた
  （未定義動作）。正しい `(const void *, const void *)` 署名に修正。

移植性レイヤ:

- `win.h` を `compat.h` に置き換え、`UNIX` / `WINDOWS` / `MSDOS` / `BCC` /
  `LSI_C` の手動切り替えをWin32とPOSIXの実際の分岐に整理。feature-testマクロを
  設定するため、各 `.c` の最初の `#include` である必要がある。
- DOS用ファーポインタ（LSI-C）版とBorland C版のメモリ上ファイル層、Win16 GUI用の
  エントリポイント（`mml_smf`、`setjmp`/`longjmp` によるエラー処理、`hWnd3`、
  `InvalidateRect`/`UpdateWindow` のダミー）を削除。
- `isascii()`（標準Cではなく、MSVCには存在しない）を、`EOF` を正しく偽と判定する
  明示的な範囲チェックに置き換え。
- `read()` / `write()` が短い転送と `EINTR` をループするように修正
  （`<errno.h>` 未インクルードのため `EINTR` の再試行が無効化されていた）。
- パイプからの読み込みに対応（`fdopen2` が `fstat` のサイズ報告に依存しなくなった）。

修正した不具合:

- **`EX` / `EE` でのスタックバッファオーバーフロー** — `getexclusive()` が
  `int exclusive[1024]` に境界チェックなしで書き込んでいた。新エラー
  71番 `"exclusive data too long"` を追加。
- **乱数ベロシティでのゼロ除算** — `kr1`（または `kr n,0`）で除数が0になった。
- **`text[]` のオーバーフロー** — 8KB固定バッファへ `strcat` で追記しており、
  `S` コマンドの多いトラックで溢れた。`text_cat()` に集約し、`Msg[]` への
  `sprintf` / `wsprintf` はすべて `snprintf` に変更。
- **タイトル/著作権表示のoff-by-one** — 長さは1バイトで書き出されるのに256を許して
  おり、長さ0として書き出されていた。上限を255に修正。
- **早期エラー時のヌル参照** — `free_all_macros()` がエラー経路から呼ばれ、
  `init_all_macros()` の実行前に `mcrstr` を参照していた。
- **`realloc` のリーク** — `reallocmacro()` と `getLine()` で、結果をブロックへの
  唯一のポインタへ代入していた。
- `put_cpres` の宣言が `static` で定義が非staticだった。
- `setcode_I()` の死んだ状態 `dir[]`（書くだけで読まれない）を削除。

テスト:

- `sample/*.mml` をすべてコンパイルしてSHA-256を照合する回帰テスト
  （`test/baseline.sha256`、`ctest`、`make check`）を追加。
- ベースラインは同梱の `.mid`（オリジナル版が生成したもの）と照合して検証済み。
  32件中28件がバイト単位で完全一致。残り4件の原因は [test/README.md](../test/README.md)。
